### 🔴 Задача #9 (P0): Сброс учёта трафика — **ЗАКРЫТА**

**Коммит:** `0a3cc14` (27.08, 32 минуты назад)

**Решение:** Добавлена колонка `carriedOverPeriodBytes` в `subscriptionsTable`

**Как работает:**
1. **При превышении лимита** (`trafficPolling.ts`):
   - Все активные ключи отзываются (`revokedReason: 'traffic_limit'`)
   - Их накопленный расход (`periodUpBytes + periodDownBytes`) **банкуется** в подписку:
     ```typescript
     const revokedBytes = keysToRevoke.reduce(
       (sum, { key }) => sum + key.periodUpBytes + key.periodDownBytes, 0
     );
     await tx.update(subscriptionsTable)
       .set({ carriedOverPeriodBytes: sql`${subscriptionsTable.carriedOverPeriodBytes} + ${revokedBytes}` });
     ```

2. **При проверке лимита**:
   - Считает `activeKeyPeriodBytes` (сумма по активным ключам)
   - Добавляет `carriedOverPeriodBytes`:
     ```typescript
     const periodBytes = Number(r.activeKeyPeriodBytes) + r.carriedOverPeriodBytes;
     ```

3. **При докупке трафика**:
   - Новый ключ создаётся с `periodUpBytes = 0`
   - Но `carriedOverPeriodBytes` сохраняется → расход не теряется
   - Пользователь получает **ровно купленное**, а не полный новый лимит

**Миграция:** `heal-schema.mjs` M-42 добавляет колонку с `DEFAULT 0`

**Тесты:** Добавлен сценарий `4c` в `balanceCheckout.test.ts` — проверяет concurrent payment race

**Оценка:** 10/10 — элегантное решение, сохраняет расход в подписке, не требует retry queue

### 🟡 Задача #10 (P2): 23505 → 409 — **ЗАКРЫТА**

**Коммит:** `0a3cc14` (тот же)

**Решение:** Обработка PostgreSQL unique violation в `balanceCheckout.ts`

**Как работает:**
```typescript
const pgCode = err?.code ?? err?.cause?.code;
if (pgCode === "23505") {
  logger.info({ userId, paymentType }, "balance_checkout: concurrent insert lost race");
  return { ok: false, status: 409, error: "concurrent_payment_conflict" };
}
```

**Сценарий:** Два одновременных платежа на разные суммы (разные планы) → один выигрывает unique index, другой получает `409 concurrent_payment_conflict` вместо `500`

**Тест:** `scenario 4c` в `balanceCheckout.test.ts` — проверяет, что проигравший получает `409`, баланс списывается ровно один раз

**Оценка:** 9/10 — корректная обработка race condition

### 🟢 UI-фикс админа — **ЗАКРЫТ**

**Коммит:** `2700eec` (27.08, 1 час назад)

**Решение:** Автоподстановка email админа в поиск ключей

**Как работает:**
```typescript
useEffect(() => {
  if (!adminSearchDefaulted && isAdmin && me?.email) {
    setAdminKeySearch(me.email);
    setAdminSearchDefaulted(true);
  }
}, [adminSearchDefaulted, isAdmin, me?.email]);
```

**Результат:**
- Админ видит **только свои ключи** по умолчанию (поиск = его email)
- Чтобы посмотреть чужие — нужно осознанно очистить поиск
- Верхний блок (ссылка подписки, QR, конфиги обхода РФ) использует `myActiveKeys` (только `userId === me.id`)

**Оценка:** 9/10 — простое и эффективное решение

### 🔧 Фикс сборки ssh2/cpu-features

**Коммит:** `4aa740e` (26.08, 20 часов назад)

**Решение:** Добавлены в `onlyBuiltDependencies` в `pnpm-workspace.yaml`:
```yaml
onlyBuiltDependencies:
  - '@swc/core'
  - cpu-features  # ← добавлено
  - esbuild
  - msw
  - protobufjs
  - ssh2          # ← добавлено
  - unrs-resolver
```

**Причина:** pnpm по умолчанию не собирает нативные модули (Node.js native addons). `ssh2` и `cpu-features` требуют компиляции C++ кода при установке.

**Оценка:** 10/10 — минимальное изменение, решает проблему сборки
