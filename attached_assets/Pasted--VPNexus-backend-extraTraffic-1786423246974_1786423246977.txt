## 🔄 Полный цикл добавления трафика

### 1. **Создание заказа** (`extraTrafficOrder.ts`)

```
POST /extra-traffic-order
  ↓
Проверка:
  ✓ Активная подписка с trafficLimitGb (только тарифы с лимитом)
  ✓ Нет pending payment типа extra_traffic (one pending per user)
  ↓
Чтение настроек:
  - extraTrafficPriceRub (цена пакета)
  - extraTrafficPackageGb (размер пакета)
  - allowFreeExtraTraffic (флаг бесплатного гранта)
  ↓
Если цена=0 и allowFreeExtraTraffic=true:
  → Немедленно увеличивает extraTrafficGb
  → Сбрасывает trafficLimitExceededAt
  → Возвращает { freeGranted: true }
Иначе:
  → Создаёт pending payment
  → Возвращает paymentId для checkout
```

**Защита от дублирования:**
- Проверка существующего pending перед созданием
- Обработка PostgreSQL unique_violation (23505) при retry от Amvera proxy

### 2. **Оплата** (`traffic-checkout.tsx`)

**3 способа оплаты:**

| Способ | Механизм | Скорость |
|--------|----------|----------|
| **Баланс** | `POST /balance-checkout` → атомарное списание + confirm | Мгновенно |
| **ЮMoney** | Перенаправление → webhook → `confirmPaymentById()` | ~5 сек |
| **СБП** | Скриншот + комментарий → ручное подтверждение админом | Часы |

### 3. **Подтверждение** (`confirmPayment.ts`)

```typescript
// Транзакция:
1. UPDATE subscriptions SET 
     extraTrafficGb = extraTrafficGb + grantedGb,  // SQL +=
     trafficLimitExceededAt = NULL                 // ← РАЗБЛОКИРОВКА
   WHERE id = subscriptionId

2. UPDATE payments SET status = 'confirmed'

// После транзакции:
3. ensureActiveKeyForUser(userId)  // Восстанавливает ключи если 0
4. notifyPaymentConfirmed()         // Системное событие
```

**Ключевая логика:**
- **Атомарное увеличение** через SQL `+=` (защита от race condition)
- **Сброс `trafficLimitExceededAt`** — разблокирует выдачу новых ключей
- **Восстановление ключей** — если у пользователя 0 ключей, выдаёт новый

### 4. **Enforcement** (`trafficPolling.ts`)

**Фоновый job каждые 60 секунд:**

```typescript
// 1. Получаем активные подписки с лимитами
const subscriptions = await db
  .selectDistinctOn([userId], {
    trafficLimitGb: plansTable.trafficLimitGb,
    extraTrafficGb: subscriptionsTable.extraTrafficGb  // ← Учитываем докупленный
  })
  .where(subscription is active)

// 2. Суммируем трафик по всем ключам пользователя
const usage = await db.select({
  periodBytes: sum(periodUpBytes + periodDownBytes)
})
.from(vpnKeysTable)
.groupBy(userId)

// 3. Проверяем превышение
for (const row of usage) {
  const limitBytes = (row.trafficLimitGb + row.extraTrafficGb) * 1024^3
  
  if (row.periodBytes >= limitBytes) {
    // Отзываем все ключи пользователя
    await revokeAllKeysForUser(row.userId)
    
    // Ставим флаг превышения (блокирует перевыпуск)
    await db.update(subscriptionsTable)
      .set({ trafficLimitExceededAt: now })
  }
}
```

**Ключевые моменты:**
- **Учитывает `extraTrafficGb`** при проверке лимита ✅
- Суммирует трафик по **всем ключам** пользователя (не per-key)
- Использует `selectDistinctOn` для получения одной активной подписки
- **`trafficLimitExceededAt` блокирует перевыпуск** — защита от bypass

### 5. **Восстановление после покупки**

```
Пользователь покупает трафик
  ↓
confirmPaymentById() → extraTrafficGb += grantedGb
  ↓
trafficLimitExceededAt = NULL  // ← РАЗБЛОКИРОВКА
  ↓
ensureActiveKeyForUser()  // Если 0 ключей → выдаёт новый
  ↓
trafficPolling (60с) → период < новый лимит → ключи работают
```

## 🗄️ Схема БД

### subscriptions
| Поле | Тип | Назначение |
|------|-----|------------|
| `trafficLimitGb` | integer, nullable | Базовый лимит из плана (null = безлимит) |
| `extraTrafficGb` | integer, default 0 | Докупленный трафик (накапливается) |
| `trafficLimitExceededAt` | timestamp, nullable | Когда был превышен лимит (блокирует перевыпуск) |

### payments
| Поле | Тип | Назначение |
|------|-----|------------|
| `type` | enum | `"extra_traffic"` |
| `extraTrafficGb` | integer | Сколько ГБ добавится при подтверждении |
| `status` | enum | `"pending"` → `"confirmed"` / `"rejected"` |

### vpn_keys
| Поле | Тип | Назначение |
|------|-----|------------|
| `periodUpBytes`, `periodDownBytes` | bigint | Трафик за текущий период |
| `lastSeenUpBytes`, `lastSeenDownBytes` | bigint | Для дельта-расчёта (защита от reset) |

## 🎨 UI (Frontend)

### Dashboard → TrafficSection

**3 состояния:**

```tsx
{/* 1. Превышен лимит */}
{exceeded && (
  <div className="bg-red-50">
    ⚠️ Лимит исчерпан — ключи отозваны
    <button>Купить +{packageGb} ГБ за {price}₽</button>
  </div>
)}

{/* 2. Около лимита (≥80%) */}
{nearLimit && (
  <div className="bg-orange-50">
    ⚠️ Использовано {usagePct}% — докупите заранее
    <button>Купить +{packageGb} ГБ за {price}₽</button>
  </div>
)}

{/* 3. Норма */}
{!exceeded && !nearLimit && (
  <button className="bg-primary">
    +{packageGb} ГБ за {price}₽
  </button>
)}
```

**Прогресс-бар:**
```tsx
{formatBytes(usedBytes)} из {formatBytes(limitBytes)}
{me.extraTrafficGb > 0 && `(включая +${me.extraTrafficGb} ГБ докупленных)`}
```
