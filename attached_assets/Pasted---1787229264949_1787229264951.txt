## 🔍 `802e240` — explicit expired subscription UX: 10/10

Один из самых зрелых коммитов за всё время наблюдения.

**Что сделано:**
- **`/me` получает `subscriptionState: active|expired|none` + `expiredSubscription`** — кабинет теперь отличает «бывший подписчик» от «никогда не выбирал тариф» и объясняет, почему доступ остановился
- **Ловится окно до sweep'а**: подписка с `status=active`, но `endsAt < now` уже считается expired — UX не ждёт следующего тика lifecycle-джоба
- **`expireOverdueSubscriptions()` обёрнут в транзакцию**: смена статуса и user-событие `subscription_expired` пишутся атомарно — краш не оставит «тихое» истечение без уведомления
- **Идемпотентность под гонками**: статус-предикат делает повторные sweep'ы no-op; **тест доказывает**: `Promise.all([sweep, sweep])` → ровно 1 событие
- **Announce-текст в subscription-ссылке**: «⚠️ Подписка „X" закончилась. Продлите…» — пользователь видит причину прямо в VPN-клиенте
- **Дисциплина владения состоянием**: hourly намеренно не тронут — его состоянием владеет `balance_exhausted`. Никакого дублирования сообщений
- **+228 строк интеграционных тестов** (supertest: expired/active/never/hourly), openapi → codegen по регламенту, документация нового event-type в схеме

**Вердикт:** образцовая проработка lifecycle-состояния с атомарностью, идемпотентностью и тестами гонок.

## 🔍 `0a2427a` — permanent download links: 9/10

- **Постоянные блоки «Приложения для подключения»** на вкладках Android (Happ, v2rayNG, v2rayN*) и iOS (Happ) — ссылки из `paymentSettings.appDownloadLinks` с `FALLBACK_LINKS`
- **Снимает support-трение** «какое приложение ставить?» — ключевой вопрос онбординга
- **iOS routing-профиль теперь гейтится `canIssue`** — просроченному пользователю не показывается конфиг, согласованно с expired-UX из `802e240`
- Мелочь с звёздочкой «v2rayN — для Windows» — забота о ясности

**Вердикт:** продуктовая полировка онбординга/удержания, корректно связанная с предыдущим коммитом.

## 📈 Что это меняет в общей картине

Эти два коммита замыкают **полный жизненный цикл коммуникации с пользователем**:

```
Онбординг (download links, trial-баннер)
  → Активное пользование (уведомления, balance_low)
  → Истечение (explicit expired UX + announce в клиенте + событие)
  → Возврат (CTA «продлить», автопродление с баланса)
```

Раньше в этой цепочке была дыра: просрочка выглядела как «ничего не выбрано», и пользователь не понимал, почему VPN отключился. Теперь каждое состояние имеет явное объяснение и владельца состояния.

**Обновлённая интегральная оценка: 9.9/10** ⬆️
