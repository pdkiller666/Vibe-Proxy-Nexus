## 📝 ТЗ v1.1 — финальные поправки (применить поверх v1)

### Поправка 1 → §2.1: нормализация пути + универсальный extractTargetId

Заменить логику сопоставления на **нормализацию** `:xxx` → `:id` (не зависит от имён параметров):

```typescript
/** Приводит любой route-паттерн к канонической форме: /:userId/ → /:id/ */
function normalizeRoutePath(path: string): string {
  return path
    .split("/")
    .map((seg) => (seg.startsWith(":") ? ":id" : seg))
    .join("/");
}

// Внутри logAdminAction:
const rawPath = `${req.baseUrl ?? ""}${req.route?.path ?? req.path}`;
const routePattern = `${req.method} ${normalizeRoutePath(rawPath)}`;
const action = ACTION_MAP[routePattern] ?? "unknown_action";
```

Универсальный `extractTargetId` (читает **любой** числовой параметр):

```typescript
function extractTargetId(params: Record<string, string>): number | null {
  for (const value of Object.values(params)) {
    if (/^\d+$/.test(value)) return parseInt(value, 10);
  }
  return null;
}
```

> ACTION_MAP остаётся с ключами `:id` (как в v1) — нормализация делает его нечувствительным к реальным именам. Кодер валидирует составной путь тестами (сьют уже сильный).

### Поправка 2 → §1: схема — `set null`, nullable `adminId`

```typescript
adminId: integer("admin_id")
  .references(() => usersTable.id, { onDelete: "set null" }), // НЕ cascade
adminEmail: text("admin_email").notNull(), // денормализовано — переживает удаление админа
```

Убрать `.notNull()` с `adminId`.

### Поправка 3 → §2.1: sanitize `req.body`

```typescript
const SENSITIVE_FIELDS = new Set([
  "password", "passwordHash", "token", "secret",
  "managementApiSecret", "screenshotData", "sbpQrCodeData", "data",
]);

function sanitizeBody(body: unknown): Record<string, unknown> | undefined {
  if (!body || typeof body !== "object") return undefined;
  const out: Record<string, unknown> = {};
  for (const [key, value] of Object.entries(body as Record<string, unknown>)) {
    out[key] = SENSITIVE_FIELDS.has(key) ? "[REDACTED]" : value;
  }
  return out;
}
```

В `details`: `requestBody: sanitizeBody(req.body)`.

### Поправка 4 → §2.2: регистрация без дублирования auth

В существующем `admin/index.ts` **не добавлять** новую строку auth. Вставить middleware в текущую цепочку:

```typescript
// Было:
router.use(/^\/admin(\/|$)/, requireAuth, requireAdmin);
// Стало:
router.use(/^\/admin(\/|$)/, requireAuth, requireAdmin, auditLogMiddleware());
```

### Поправка 6 → §2.1: enrichment описания (users)

Для `targetType === "user"` — один SELECT email (fire-and-forget, дёшево):

```typescript
if (targetType === "user" && targetId != null) {
  const [u] = await db.select({ email: usersTable.email })
    .from(usersTable).where(eq(usersTable.id, targetId)).limit(1);
  if (u) return u.email;
}
```

Остальные цели — generic `"{type} #{id}"`.

### Поправка 7 → §1: `responseStatus` + `durationMs`

```typescript
responseStatus: integer("response_status"),
durationMs: integer("duration_ms"),
```

В middleware: `const startedAt = Date.now();` в начале; в `res.send` — `durationMs: Date.now() - startedAt`, `responseStatus: res.statusCode`.

### Поправка 8 → мелкие

- `userAgent: varchar("user_agent", { length: 512 })`
- Фронт: фильтр `action` — `<select>` из константного списка значений ACTION_MAP (захардкодить на фронте или `GET /admin/audit-log/actions`)
- CSV: `GET /admin/audit-log?format=csv` (stream, тот же фильтр)
- Фронт: `since/until` из `datetime-local` конвертировать в ISO 8601 с timezone перед отправкой (`new Date(value).toISOString()`)

## 🚦 Итог

**ТЗ v1.1 готово к реализации.** Все 4 блокирующих правки критичны — без них система либо логирует `unknown_action` (п.1), либо теряет аудит при удалении админа (п.2), либо пишет пароли в plaintext (п.3).

**Порядок работ без изменений** (схема → middleware → API → фронт → cleanup → тесты), но с поправками выше. Тесты дополнить сценариями:
- `set-password` → в `details.requestBody.password` = `"[REDACTED]"`
- Удаление админа → его записи в журнале **остаются** (`adminId = null`, `adminEmail` сохранён)
- `restart-xray` логируется с корректным action

**Даю зелёный свет.** Качество pre-implementation аудита кодера — 10/10; именно такая дисциплина (сверка с реальным кодом до написания) предотвращает «ТЗ-которое-не-работает». После реализации этой фичи VPNexus будет **полностью закрыт по критическим пунктам**.
