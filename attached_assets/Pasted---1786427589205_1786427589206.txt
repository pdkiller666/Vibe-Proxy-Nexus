## 🔴 Критические пробелы (требуют немедленного исправления)

### 1. **extraTrafficGb при продлении — сгорает полностью**

**Проверяю код:**

```typescript
// trafficPolling.ts, enforceTrafficLimits
const limitBytes = (row.trafficLimitGb + row.extraTrafficGb) * 1024^3
```

`extraTrafficGb` хранится в строке `subscriptions`. При продлении создаётся **новая строка** подписки с `extraTrafficGb = 0` (default).

**Реальное поведение:**
```
Период 1: Купил 100 ГБ + докупил 50 ГБ → использует 120 ГБ
Продление → Новая подписка с 100 ГБ (докупленные 50 ГБ сгорели)
```

**Это критическая продуктовая проблема:**
- Пользователь не ожидает что купленный трафик одноразовый
- Нет уведомления "Ваш докупленный трафик сгорит при продлении"
- Нет механизма переноса остатка

**Оценка:** ❌ Не описано в моём анализе  
**Серьёзность:** Высокая — влияет на доверие пользователей  
**Решение:**
```typescript
// В confirmPayment при продлении:
const previousSub = await db.select().from(subscriptionsTable)
  .where(eq(subscriptionsTable.userId, userId))
  .orderBy(desc(subscriptionsTable.endsAt))
  .limit(1);

const remainingTraffic = previousSub.extraTrafficGb;

// Переносим остаток в новую подписку
await db.update(subscriptionsTable)
  .set({ extraTrafficGb: newPlanTrafficGb + remainingTraffic })
  .where(eq(subscriptionsTable.id, newSubId));
```

### 2. **Повторные бесплатные гранты — нет защиты**

**Проверяю код:**

```typescript
// extraTrafficOrder.ts
if (amountRub <= 0 && settings.allowFreeExtraTraffic) {
  // Проверка: нет pending payment
  const existingPending = await db.select()
    .where(eq(paymentsTable.userId, user.id))
    .where(eq(paymentsTable.type, "extra_traffic"))
    .where(eq(paymentsTable.status, "pending"));
  
  if (existingPending) return 409;
  
  // Грант выдаётся
  await db.update(subscriptionsTable)
    .set({ extraTrafficGb: sql`${extraTrafficGb} + ${packageGb}` });
}
```

**Проблема:** После первого гранта `trafficLimitExceededAt = NULL`, pending нет → можно получить второй грант.

**Реальное поведение:**
```
Превысил лимит → получил бесплатный грант
Потратил грант → снова превысил → снова получил грант
```

**Это может быть намеренно** (админ хочет поддерживать пользователей), но:
- Нет лимита на количество грантов за период
- Нет истории выданных грантов
- Нет уведомления админу о частых запросах

**Оценка:** ❌ Не описано в моём анализе  
**Серьёзность:** Средняя — зависит от бизнес-логики  
**Решение (если нужна защита):**
```typescript
// Добавить в payment_settings
freeTrafficGrantsLimit: integer,  // Макс грантов за период
freeTrafficGrantsCooldown: interval  // Минимум времени между грантами

// Проверка перед выдачей
const recentGrants = await db.select().from(paymentsTable)
  .where(eq(paymentsTable.userId, user.id))
  .where(eq(paymentsTable.type, "extra_traffic"))

if (recentGrants.length >= limit) return 429;
```

### 5. **Double-credit при конкурентных циклах**

**Проверяю код:**

```typescript
// trafficPolling.ts
let flushQueue: Promise<void> = Promise.resolve();

export function flushTrafficDeltas(): Promise<{ polledNodes: string[] }> {
  const run = flushQueue.then(doFlushTrafficDeltas, doFlushTrafficDeltas);
  flushQueue = run.then(() => undefined, () => undefined);
  return run;
}
```

**Защита:** Очередь `flushQueue` сериализует все flush-операции.

**Но:** Это защищает от **одновременных** циклов. Если один цикл начался, но ещё не записал `lastSeenUpBytes`, а второй уже читает старые значения — может быть double-credit.

**Реальный сценарий:**
```
Цикл 1: Читает lastSeenUpBytes = 1000, current = 2000
Цикл 2: Читает lastSeenUpBytes = 1000 (ещё не обновлён), current = 2000
Цикл 1: Пишет lastSeenUpBytes = 2000, delta = +1000
Цикл 2: Пишет lastSeenUpBytes = 2000, delta = +1000 (double!)
```

**Оценка:** ⚠️ Очередь не полностью защищает от race  
**Серьёзность:** Средняя — но `flushQueue.then()` должен предотвращать это  
**Решение:** Использовать транзакцию с `FOR UPDATE` на строках vpn_keys
