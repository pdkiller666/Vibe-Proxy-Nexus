## ❌ Критическая проблема #1: Middleware не ловит 204-ответы

### Заявлено кодером:
> "Переход на `res.on('finish', ...)` вместо патча `res.send`"

### Реальное состояние кода (`auditLog.ts` строки 178-200):
```typescript
export function auditLogMiddleware() {
  return async (req, res, next) => {
    const startedAt = Date.now();
    const originalSend = res.send.bind(res);
    res.send = function (this: Response, body?: unknown): Response {
      // ... логирование ...
      return originalSend(body);
    };
    next();
  };
}
```

**Middleware всё ещё patch'ит `res.send`, а не использует `res.on('finish')`.**

### Влияние:
Все маршруты, возвращающие `res.status(204).end()` или `res.sendStatus(204)`, **не логируются**:

| Маршрут | Код ответа | Статус логирования |
| :--- | :--- | :---: |
| `POST /admin/users/:userId/ban` | `res.status(204).end()` | ❌ НЕ логируется |
| `POST /admin/users/:userId/unban` | (предположительно 204) | ❌ НЕ логируется |
| `POST /admin/users/:userId/force-logout` | (предположительно 204) | ❌ НЕ логируется |
| `DELETE /admin/users/:userId` | `res.sendStatus(204)` | ❌ НЕ логируется |
| `DELETE /admin/plans/:planId` | `res.sendStatus(204)` | ❌ НЕ логируется |
| `DELETE /admin/vpn-keys/:keyId` | `res.sendStatus(204)` | ❌ НЕ логируется |
| `DELETE /admin/invite-links/:linkId` | `res.sendStatus(204)` | ❌ НЕ логируется |

**Это объясняет, почему бан пользователя не отображается в журнале.**

## ❌ Критическая проблема #4: normalizeRoutePath не нормализует числовые сегменты

### Заявлено кодером:
> "normalizeRoutePath теперь нормализует числовые сегменты пути"

### Реальное состояние кода (`auditLog.ts` строки 114-120):
```typescript
function normalizeRoutePath(path: string): string {
  return path
    .split("/")
    .map((seg) => (seg.startsWith(":") ? ":id" : seg))  // ❌ Только :xxx → :id
    .join("/");
}
```

**Числовые сегменты (например, `/admin/users/42/ban`) не заменяются на `:id`.**

Это значит, что если `req.route` недоступен (edge case), путь `/admin/users/42/ban` не совпадёт с `POST /admin/users/:id/ban` в ACTION_MAP.
